# Dataset card — `sample_reviews_SYNTHETIC.csv`

> **This dataset is synthetic.** Every review, restaurant and number was generated by
> [`scripts/generate_synthetic_data.py`](../scripts/generate_synthetic_data.py).
> It contains no real customer data, and no finding from it describes real customers.

## Why synthetic?

Public review datasets rarely include **delivery time** and **order value**, and none we
found has the full schema this project needs. A generated dataset also has a key
advantage for development: we know which patterns were built in, so we can check that
the analysis finds them, and we have ground-truth labels to evaluate the AI step later.

## Files

| File | Rows | Purpose |
|---|---|---|
| `sample_reviews_SYNTHETIC.csv` | 3,193 | The messy file a user would upload |
| `sample_reviews_SYNTHETIC_ground_truth.csv` | 3,101 | True sentiment, topic and issue for each original review (used in phase 2 to measure AI accuracy) |

Regenerate with `python -m scripts.generate_synthetic_data` (seed 42 by default; same seed → same file).

## Columns

| Column | Description |
|---|---|
| `review_id` | Identifier such as `R00412` |
| `review_text` | Free-text review, built from templates with varied phrasing |
| `rating` | Star rating 1–5 (some deliberately invalid) |
| `date` | Jan 2025 – Jun 2026, in several formats |
| `restaurant` | One of 12 fictional restaurants |
| `category` | Cuisine of the restaurant (11 values) |
| `delivery_time` | Minutes from order to delivery |
| `order_value` | Order total in unspecified currency units |

## Patterns built into the data

These are **assumptions written into the generator**, listed so nobody mistakes them for discoveries.

| Rule | Where in the code |
|---|---|
| Review volume grows ~3% per month; December is 40% busier | `MONTHLY_GROWTH`, `DECEMBER_VOLUME_BOOST` |
| Late delivery is the most common complaint; delivery time is 20–60 min longer when it occurs | `ISSUES`, `Generator.review` |
| Burger Barn and Slice Republic get about 2× more late-delivery complaints | `RESTAURANTS` |
| Golden Wok: spills/leaks ×3 · Spice Route: missing items ×2.5 · Shawarma Corner: cold food ×2.2 · Sakura Sushi House: pricing complaints ×2.5 | `RESTAURANTS` |
| Green Bowl and Cedar Grill have fewer complaints overall | `negative_factor` |
| App crashes ×4 in Sep–Oct 2025 (a simulated buggy release) | `time_multipliers` |
| Fee complaints ×2.5 from Mar 2026 (a simulated new service fee) | `time_multipliers` |
| Late deliveries rise gradually through 2026 (up to ×1.6) | `time_multipliers` |
| 4% of star ratings contradict the review text (a simulated mis-click) | `RATING_NOISE_RATE` |
| Mixed reviews ("Food was great but it arrived late") make up ~10% | `BASE_MIXED` |

## Data-quality problems injected on purpose

| Problem | Approx. rate |
|---|---|
| Dates in 4 formats (`2025-03-05`, `2025-03-05 18:30:00`, `March 05, 2025`, `05 Mar 2025`) | 20% non-ISO |
| Unreadable or future dates | 0.5% |
| Messy-but-valid ratings (`4/5`, `4 stars`, `four`) | 1.3% |
| Invalid ratings (`6`, `0`, `-1`, `abc`, empty) | 1% |
| Empty or placeholder review text (`""`, `N/A`) | 1.5% |
| HTML tags / extra whitespace in text | 1% |
| Restaurant name typed in different cases or with spaces | 2% |
| Delivery time with units (`35 min`), missing, or impossible (`-5`, `999`) | ~4.5% |
| Order value with currency (`$45.50`, `SAR 45.50`), missing, or impossible | ~4.3% |
| Missing `review_id` | 0.5% |
| Exact duplicate rows | 2% |
| Same review re-submitted under a new id | 1% |

## Known limitations

- Reviews are template-based. About 20% of review texts appear more than once (mostly
  short ones such as "Great food!"), and the language is cleaner and more predictable
  than real reviews. **AI accuracy measured on this data will overstate real-world accuracy.**
- Monthly samples are small (140–240 reviews), so built-in time effects are partly hidden
  by random variation. This is realistic, and the analytics report significance accordingly.

# Dataset card — `raw/reviews.csv` (apparel e-commerce demo)

> **Real, anonymised third-party data.** Download it yourself from Kaggle
> ([Women's E-Commerce Clothing Reviews](https://www.kaggle.com/datasets/nicapotato/womens-ecommerce-clothing-reviews))
> and save it as `data/raw/reviews.csv`. It is not committed to this repository. Check the
> dataset's licence on Kaggle before redistributing it or anything derived from its text.

## Schema and mapping (profile `apparel_ecommerce`)

| Source column | Feedlytics column | Role | Notes |
|---|---|---|---|
| *(unnamed index)* | `review_id` | id | Row number from a pandas export; ignored when detecting duplicates |
| Clothing ID | `product_id` | entity ("Product") | 1,206 products; only 192 have ≥15 reviews |
| Age | `age` → `age_band` | numeric → segment | Banded only (Under 30 … 60+); 18–99 in the data |
| Title | `review_title` | title | Missing for 3,810 rows; combined with the text for AI labelling |
| Review Text | `review_text` | text | Missing for 845 rows |
| Rating | `rating` | rating 1–5 | Skewed: 56% are 5★, 10% are 1–2★ |
| Recommended IND | `recommended` | outcome | 1 = recommends; 98.5% agreement with clearly positive/negative ratings |
| Positive Feedback Count | `helpful_votes` → `helpful_votes_band` | numeric → band | Helpfulness votes from other shoppers |
| Division / Department / Class Name | `division`, `department`, `product_class` | segments | The source spells "Initmates"; the profile corrects it to "Intimates" |

## What cleaning does to it

23,486 rows → **23,465** kept:
- 21 duplicate rows are removed (identical apart from the row number; 20 of them have no text).
- 825 rows have no review text but are kept for rating statistics; one of them has a title only.
- 3,769 reviews are flagged as **cut off by the source** at ~508 characters.

## Limitations

- **No dates:** trend analysis is not possible with this dataset.
- **Truncated text:** about one in six reviews (17%) ends mid-sentence, so the AI can't see the rest.
- **Long tail of products:** most products have too few reviews for reliable comparisons,
  and the analysis marks them as such.
- **No ground-truth labels:** accuracy must be measured with a hand-labelled sample
  (`scripts/make_labeling_sample.py`).
